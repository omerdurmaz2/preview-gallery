# Snapshot Coverage, Reference Images and Health

**Status:** shipped · **Phases:** PG13 · PG14 · PG15 · PG16 · PG18 · PG19 (reference-view half) · PG24-1 (reference-strip half) · **Last change:** `19908b0` [PG24-1] 2026-08-20

Badges every preview row with whether its composable has a Compose Preview Screenshot Testing snapshot, shows the committed golden PNGs for a snapshot row or (in reference mode) for a covered preview, and reports coverage and snapshot health as Markdown. Everything here reads only committed sources and `src/screenshotTest*/reference` directories on disk — it never renders a `screenshotTest` composable and never runs Gradle. The one extension left open, comparing a live render against a golden, is a separate roadmap item (F5's diff half) gated on work outside this area.

## What the user gets

- Every preview row carries a grayed badge: `· 1 snapshot` / `· N snapshots` / `· no snapshot`, drawn on **every** row regardless of whether its module ever adopted screenshot testing — there is no "not applicable" state (see Key decisions).
- A snapshot appears as a **child row** of the preview whose composable it covers. A snapshot matching no preview in its module lands under that module's own "Snapshots without a preview" branch.
- Selecting a **snapshot row** shows its committed reference PNGs stacked top to bottom at one shared zoom, each with its own variant label underneath. A snapshot with nothing committed shows "No reference images — run `<task>`", naming the module's own `update<Variant>ScreenshotTest`(s), or a generic sentence when no variant can be read.
- A render-pane toolbar toggle, **"Show committed reference images"** (a Diff icon), appears only for a covered, non-snapshot preview row. Turning it on is sticky across selection: every covering snapshot's goldens show in one strip, labelled by snapshot name only when more than one snapshot covers the preview; an uncovered preview keeps rendering live while the mode stays on, and the toggle disappears for a preview with nothing to show.
- Gallery toolbar: a second persistent toggle, **"Show only previews without a snapshot"** (dashed-frame icon), hides every covered preview; the orphan branch stays visible while it is on. An empty result under this filter reports itself distinctly from "no active module" or "no query match".
- Gallery toolbar: **"Export snapshot coverage report"** writes a Markdown file (save dialog) describing the whole project's coverage — never the filtered tree — followed by an appended `## Health` section flagging blank committed goldens and rows whose name claims a component their body never calls.
- The reference strip shares its zoom/pan gestures (wheel, Ctrl+wheel, trackpad pinch) with the live render view as of PG24-1; see the render-view doc for `ViewportGestures` itself.

## How it works

1. **Index/scan.** `PreviewPsiScanner` flags `isSnapshotTest` on any function carrying `@PreviewTest` directly (recognised import-locally, like `@Preview`) and extracts `targets` — the composables the body calls — via `TargetExtractor`, which descends only through trailing lambdas and keeps only PascalCase callee names, so wrapper calls (`PreviewComponent { PrimusTheme { … } }`) and argument-list state factories are excluded without a configured deny-list. See the catalogue doc for `PreviewIndex`/`PreviewPsiScanner` itself.
2. **Two channels feed `PreviewIndexService`.** `PreviewIndex` (`FileBasedIndex`) sees ordinary previews; `SnapshotSourceScanner` independently probes every module's content roots for a `src/screenshotTest` directory, attributes a shared directory to the `.main` (or shortest-named) module, and re-parses its files directly from the VFS with the **same** `PreviewPsiScanner`. This exists because a module-per-source-set Gradle import puts `src/screenshotTest` under a holder module the previews never live in, and because the source set may not be in the project model at all when synced without `-Pandroid.experimental.enableScreenshotTest=true`. An index row is dropped only when its file lies inside a directory the scanner already walked; elsewhere the index is the only channel and is kept, so a directory layout the scanner's probe does not recognise still surfaces.
3. **`SnapshotCoverageResolver.resolve`** partitions the joined rows into previews/snapshots by `isSnapshotTest`, then matches by "same module name and share at least one target" — never by function name, since sampled real pairs (`ErrorRetryRowPreview` / `ErrorRetryRow_Default_Snapshot`) share no name-normalisation rule but do share a call target. A preview's coverage is `Covered(count)` or `Uncovered`; there is **no third state** — a module that never adopted screenshot testing is `Uncovered` on every row. Unmatched snapshots become orphans.
4. **Tree.** `PreviewTreeModelBuilder`/`PackageTreeBuilder`/`ModuleTreeBuilder` attach each snapshot leaf under its preview leaf and route orphan leaves to their module's own branch; `PreviewTreeCellRenderer` draws the badge text and the orphan-branch/snapshot rows.
5. **Reference lookup** (a selected snapshot row, or a covered preview's `snapshots` list in reference mode) runs through `ReferenceStripLoader.locate`/`decode` (moved out of `PreviewGalleryPanel` in PG19 so the preview-row mode could reuse it): resolve the module directory under a read action (`ModuleDirectoryResolver` — path derivation via `SnapshotSourceScanner.moduleDirectory` first, `ProjectFileIndex` content-root fallback second); `ReferenceRoots.refresh` the `src/screenshotTest*` directories from disk with **no read lock held** (at most once per module per lookup); list every discovered root — one per build variant/flavour — under a second read action via `ReferenceRoots.of` + `ReferenceImageLocator.locate`; decode PNGs off the EDT and outside any read action. A label is qualified with the source set only when a strip spans more than one root, and with the snapshot's own name only when a preview's strip spans more than one snapshot.
6. **Filter/report.** `PreviewCoverageFilter` (in `search/`) is a single `filter` call composed into `PreviewGalleryPanel.applyFilter` alongside the module filter and the search query. `CoverageReportAction` reads the panel's **unfiltered** rows, builds `CoverageReport.markdown(...)` + `HealthReport.markdown(SnapshotHealth.check(...), GoldenInspector.inspect(...))`, and writes the concatenation to a user-chosen file.
7. **Health.** `SnapshotHealth.check` is pure, index-data-only: a row's name-derived "stems" (every prefix once a `Preview`/`Snapshot` suffix is stripped, shortest first) are checked against the project-wide vocabulary of every row's `targets` (previews, snapshots and orphans together); a row is flagged only when a stem is a *known* component elsewhere in the project and none of the row's own `targets` call it. `GoldenInspector.inspect` decodes every committed reference PNG for the covering + orphan snapshots and reuses `RenderedImageInspector.isBlank` (in `render/`, unmodified) to flag degenerate goldens.

Selecting a snapshot row can also be superseded by a measured Verify result (`SnapshotVerifyStore`) — see the verify doc for that path; this document covers the plain committed-reference display underneath it.

## Key decisions

- A function is a snapshot iff `@PreviewTest` is written directly on it (import-local, exactly like `@Preview`); it is then **never** emitted as an ordinary preview row, even when it also matches `@Preview` — spec [2026-07-30 D1](../../superpowers/specs/2026-07-30-snapshot-coverage-badge-design.md), `b47e08f` [PG13-3].
- Coverage matches by shared `targets` within the same module name, never by function name — spec D3, `6bc58ec` [PG13-6].
- Snapshot rows are read from disk (`SnapshotSourceScanner`), not from `PreviewIndex`: a module-per-source-set Gradle import attributes `src/screenshotTest` to a holder module the previews never live in. The index was not blind; attribution was wrong. The first design draft's evidence read the opposite way and was corrected after inspecting the cached module model — spec [2026-07-31 D1/D4](../../superpowers/specs/2026-07-31-snapshot-source-set-fallback-design.md), `75178c8` [PG14-2], corrected by `16ecbe3` [PG14-5] (see History).
- Reference roots are discovered per build variant from `<moduleDir>/src/screenshotTest*/reference`, never hardcoded to `screenshotTestDebug`, and refreshed synchronously from disk **outside** any read action before every lookup — the platform rejects a synchronous refresh taken under one — spec [2026-07-31 D1-D4](../../superpowers/specs/2026-07-31-snapshot-reference-hardening-design.md), `13e4d1d` [PG15-2], `99bfdba` [PG15-3].
- `SnapshotCoverage.NotApplicable` was deleted outright after the PG16 gate: hiding modules with no `src/screenshotTest` behind it surfaced one module out of 1371 in `hepsi-android`, which read as the filter being broken rather than the project having no coverage. **Code now disagrees with the original spec D2**, which kept the third state — a module that never adopted screenshot testing is `Uncovered` on every preview, `SnapshotCoverageResolver.resolve` no longer even takes a "modules with snapshots" set, and `CoverageReport` counts every module — `88c9f1f` [PG16-6], fixed further by `37c89d1` [PG16-7].
- Only the *uncovered* direction of the coverage filter was built; *covered only* was cut for want of a second toolbar control nobody had asked for — spec [2026-08-06 Non-Goals](../../superpowers/specs/2026-08-06-snapshot-coverage-filter-design.md).
- The coverage report always describes the whole project (the panel's unfiltered `entries`), never the search/module/coverage-filtered tree — spec D5, `98629b4` [PG16-5].
- Health runs two independent checks: a blank-golden pixel check reusing `RenderedImageInspector.isBlank` unmodified, and a name-vs-target check whose vocabulary is the union of **every** row's `targets` — previews, snapshots and orphans together — so it never accuses a name of claiming a component nothing in the project actually calls — spec [2026-08-07 D1-D3, D9](../../superpowers/specs/2026-08-07-snapshot-health-design.md), `4c8d8a3` [PG18-2]. Calibrated live against `hepsi-android`: 12 findings, 9 real and 3 false positives sharing one shape (an unsuffixed function name that *is* the component, not a claim about one) — fixed by dropping the full-length stem when no suffix was stripped, `58b7f37` [PG18-10].
- The reference view is a **mode toggle** in the render pane, not a comparison tab: a tab in `viewTabs` would have taught the whole tab-strip machinery (per-tab overrides, close buttons, render generations) a "this tab is not a render" case. It reuses `RenderState.REFERENCE`/`NO_REFERENCE` and `ReferenceStripView` unchanged, stays sticky across selection, and shows an uncovered preview's live render (never an empty/error state) so the mode stays usable on a partially-covered project — spec [2026-08-10 D1-D2, D5, D7](../../superpowers/specs/2026-08-10-reference-view-design.md), `abb7b4d` [PG19-4], `2f5bcb1` [PG19-5].
- The reference strip lays out its images **stacked top to bottom**, not side by side as the original spec had it: three phone-width goldens in a row bound the shared scale on width until nothing was readable; stacking makes height the axis that grows, which a scroll pane handles well. This **supersedes** the 2026-07-30 spec's D7 — `19908b0` [PG24-1].

## Android Studio and platform internals relied on

- `VfsUtil.markDirtyAndRefresh(false, recursive, true, …)` called with **no read lock held** — the platform throws for a synchronous refresh taken under one. `ReferenceRoots.refresh` is its own step between two `ReadAction.nonBlocking` calls rather than inside either (`service/ReferenceRoots.kt`).
- `VirtualDirectoryImpl` throws `InvalidVirtualFileAccessException` for an invalidated directory only under read access and silently returns no children otherwise; `ReferenceRoots.of`/`refresh` both check `isValid` up front so a background and an EDT caller take the same early return after a directory disappears mid-lookup — `87b5108` [PG15-8].
- No Gradle/AGP model is read anywhere in this area: modules, source sets and build variants are all discovered by probing `ModuleRootManager` content roots and VFS directory names. `ExternalSystemApiUtil` was checked and confirmed **absent** from this IntelliJ Platform SDK (every jar under `Contents/lib` and `Contents/plugins/*/lib` scanned) — spec [2026-07-31 D3](../../superpowers/specs/2026-07-31-snapshot-source-set-fallback-design.md).
- `FileDocumentManager.getCachedDocument` is consulted before `VfsUtilCore.loadText`, so an unsaved editor buffer wins over the bytes on disk when `SnapshotSourceScanner`'s cheap `"Preview"` text gate runs — the same gate `PreviewIndex` applies for its own files.
- `ReadAction.nonBlocking(...).expireWith(parentDisposable).executeSynchronously()` is the split point between project-model/VFS-listing work (needs the read lock) and `ImageIO` decoding (must not hold it) throughout `ReferenceStripLoader`; a `ProcessCanceledException` from a preempted read action propagates rather than being swallowed.
- `ImageIO.read` returning `null` for an unrecognised stream vs. throwing for an IO failure are both treated as "skip and count", never fatal, in `GoldenInspector` and `ReferenceStripLoader.readImage`.

## Open items

- [gap] The coverage filter's *covered only* direction ("which snapshots am I about to invalidate?") was scoped out for want of a second toolbar control nobody had asked for — [coverage filter spec](../../superpowers/specs/2026-08-06-snapshot-coverage-filter-design.md) Non-Goals; roadmap F2.
- [limitation] F5's diff view (live render vs. committed golden) is not built: the plugin renders `main`'s `@Preview`, the golden comes from the `screenshotTest` function's own `PreviewComponent`/`PrimusTheme` wrapper, so the two are not pixel-comparable yet. Blocked on a classloader question outside this area (verify doc) — [roadmap](../../snapshot-testing-roadmap.md) F5.
- [limitation] Switching the reference mode **on** briefly shows "Nothing selected" with an empty toolbar, because `pipeline.select(null)` publishes `IDLE` synchronously before the strip lands; toggling off is smooth. Accepted at the PG19 gate as a known rough edge — [roadmap](../../snapshot-testing-roadmap.md) F5.
- [limitation] `ReferenceImageLocator.variantOf` mislabels an image when one snapshot function's name is a textual prefix of a sibling's in the same facade class (`Row` vs. `Row_Wide`); documented as "a mislabelled extra image … never a wrong or missing snapshot row" — code KDoc, [ReferenceImageLocator.kt](../../../src/main/kotlin/com/devomer/previewgallery/service/ReferenceImageLocator.kt).
- [limitation] Module attribution for a Kotlin Multiplatform import (`…androidMain`/`…commonMain`) is unsupported by design: neither name ends in `.main`, so `pickOwningModule` falls back to the shortest name (the holder module) and previews in the source-set module would read `· no snapshot`. Pinned by `SnapshotOwningModuleTest`, not reachable in `hepsi-android` today — [source-set fallback spec](../../superpowers/specs/2026-07-31-snapshot-source-set-fallback-design.md) D4.
- [limitation] `TargetExtractor` only sees an unqualified call as the single, trailing-lambda-chain statement; a qualified call (`Foo.Bar()`), a non-trailing lambda argument, or a call wrapped in `if`/`when`/`return`/`remember{}` yields no target, which reads as "never matched" rather than an error — code KDoc, [TargetExtractor.kt](../../../src/main/kotlin/com/devomer/previewgallery/index/TargetExtractor.kt).
- [debt] `PreviewGalleryPanel.publishReferences`'s staleness guard compares only the strip's *owner id*, not the row list it was built from; a PSI change that re-resolves the same preview with a different snapshot set inside the ~400 ms–2 s decode window could publish a stale strip under the right owner id. Marked `ponytail:` in code with its own upgrade path — `ui/PreviewGalleryPanel.kt`, `3514ae5` [PG19-7].
- [bug] (flaky) `PreviewGalleryPanelTest > test a snapshot the project model places in no module still shows its references` (around line 481) failed once in a full suite run on 2026-09-14, passed alone and on rerun; cause not yet isolated.
